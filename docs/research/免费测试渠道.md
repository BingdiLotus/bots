# 免费测试渠道

> 核查日期：2026-10-19。只采用官方定价、开发文档和帮助页面；未创建外部组织、服务器或 Bot，未发送真实消息。套餐与权限可能调整，以下不是已完成的渠道集成验收。
> 产品范围仍以 [Bots MVP](../MVP设计.md) 为准。用户已确认沿用 **Slack 免费自建 Bot**；其它渠道保留为后续选择，不并行建设全渠道平台。

“免费”在这里指渠道的基础试用入口，不包括模型 API、Bots/Chronotope 运行主机等成本。普通自建 Bot 与平台内置 AI、付费广播或高级管理功能分别判断。

| 渠道 | 已确认的免费范围 | 最小接入与权限条件 | 尚未确认或实施的部分 |
|---|---|---|---|
| Slack Free | 免费 workspace；官方列出最多 10 apps。普通自建 Bot 不以购买 Slack 内置 AI 为前提 | 安装自己的 Slack app，配置 Events 订阅、Bot token/scopes；发送仍受频道成员关系和当前权限约束 | 未做真实 workspace 安装及 Slack 发送验收；免费版应用数量、历史等限制仍适用 |

| Discord | 官方开发入门明确可以免费创建测试 server 并安装自己的 app | 配置安装 scope、频道权限；普通消息内容涉及 Gateway intents，命令也可通过 Interactions 接入 | 尚无 Discord 适配器；能使用命令不等于可读取所有频道消息，privileged intents 有开通/审批条件 |

## Slack：自建 Bot 与内置 AI 分开

[Slack 定价](https://slack.com/pricing)将 Free 列为 `$0`、`free forever`，并列出 `Up to 10 apps`。这与 Slack 自己的 AI 功能或其他厂商 Bot 产品的订阅要求是不同问题。

[官方开发入门](https://docs.slack.dev/quickstart/)展示创建、安装普通应用，并在私聊或频道与自己的 Bot 交互。[chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/)使用具备 `chat:write` 等所需权限的 token，`thread_ts` 指定原消息的线程。这条基础应用接入路径不需要先购买 Slack 内置 AI。

免费 workspace 仍有产品限制，组织也可能要求管理员批准安装。API [速率限制](https://docs.slack.dev/apis/web-api/rate-limits/)同样适用；收到 HTTP 429 后按 `Retry-After` 等待。当前实现保留 Slack，不能把协议测试通过写成真实 Slack 已联通。

## Telegram：long polling 适合本机试运行

[Bot Platform](https://core.telegram.org/bots)明确写明 `free for both users and developers`。接入可以选择 [long polling 或 webhook](https://core.telegram.org/bots/faq#how-do-i-get-updates)，两者互斥；已设置 webhook 时不能同时通过 long polling 收取更新。

[getUpdates](https://core.telegram.org/bots/api#getupdates)支持正数 `timeout` 做 long polling，调用方只需能出站访问 Telegram API。官方把“传入高于某条 `update_id` 的 offset”视为确认，更新在服务器上最多保留 24 小时。

因此，未来 Bots 接入时应先耐久保存输入，再推进 offset；这是 **Bots 的接入实现要求**，不是 Telegram 自动提供的 inbox/outbox 保证。超过平台保留窗口的缺失不能靠本地重启恢复。

[Privacy mode](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)会影响群聊输入：默认隐私模式主要接收发给该 Bot 的命令、相关回复等；管理员 Bot 或关闭 privacy 的 Bot 可接收更广的群消息，但仍有官方列明的例外。私聊、群聊和频道的可见性不同，不能把添加 Bot 当成读取全部会话的授权。普通 MVP 不需要启用 FAQ 中另列的付费广播。

## Discord：免费服务器不等于默认可读全部消息

[官方入门](https://docs.discord.com/developers/quick-start/getting-started.md)要求创建开发者应用、配置安装权限，并建议安装到不影响他人的测试服务器；文中明确提供“create one for free”的建服入口。

[Gateway 文档](https://docs.discord.com/developers/topics/gateway.md)将 `MESSAGE_CONTENT` 列为 privileged intent。未验证应用也需要在 Developer Portal 启用所需 intent；达到 100+ guilds 的应用验证条件后，相关 privileged intents 还需要批准。处理普通频道自然语言与处理 slash command/Interactions 是不同的接入面，不能用后者成功证明前者已经获得权限。

如果用户选择 Discord，先按选定的消息或命令入口完成一个测试服务器闭环，不把大规模分发、完整 intent 集合或社区管理平台加入当前 MVP。

## Lark 与飞书分别核对

Lark 的[定价页](https://www.larksuite.com/en_us/plans)确认有免费 Starter。其[企业自建应用流程](https://open.larksuite.com/document/home/introduction-to-custom-app-development/self-built-application-development-process.md)要求成为企业用户，可创建或加入企业；企业自建应用仅在企业内发布，由租户管理员审核，无需 Lark 团队审核。流程包括机器人能力、API 权限、事件订阅、版本发布与可用范围。

Lark 的[发送消息 API](https://open.larksuite.com/document/server-docs/im-v1/message/create.md)明确支持 Custom App，使用 `tenant_access_token`；Bot 需要已开启机器人能力及相应消息权限，向用户发送需在可用范围内，向群发送需已加入该群。该文档同时列出接口和目标的速率限制；这不等于已经确认 Starter 的全部套餐额度。

飞书大陆版的[版本对比](https://www.feishu.cn/service)与[企业自建应用流程](https://open.feishu.cn/document/home/introduction-to-custom-app-development/self-built-application-development-process.md)应单独采用。已确认的开发流程同样包括企业内部应用、企业管理员审核、能力/权限和发布；当前免费权益、调用额度及特定 API 是否受版本限制，本轮没有完整确认。不能把 Lark 的套餐、租户或应用凭据当作飞书的同一份配置。

本项目需要能接收消息事件的应用机器人。仅能向群推送的 webhook 入口，不足以证明已经具备成员请求、工具调用和回复的完整闭环。

## Discourse：存在免费计划，接口权益仍需确认

[官方 Free 页面](https://www.discourse.org/free)明确提供免费托管计划；[定价页](https://www.discourse.org/pricing)也列出 Free plan，并在 Pro 功能中列出 API and Webhook access。当前证据不足以在本项目中承诺 Free 计划具备需要的 API key/webhook 权限，须针对所选计划核对。

Discourse 是主题/帖子式社区，交互对象与即时消息频道不同。用户若选择它，再先验证免费计划的接口权益；本轮不新增 Discourse 适配器或据此调整当前 Slack MVP。
