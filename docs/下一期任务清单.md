# 下一期任务清单（trial-driven v0.2）

状态：M1/M2 代码完成；任务/记忆查询已有真实 Slack smoke；两步 forget 的请求步骤真实验证，最终 confirm 尚未在真实 Slack 成功验收；短 trial 已结束。M3/M4 仍为规划。

## 试用观察

- 用户问“没有待办吗？定时任务呢？”：当前只有创建/改期/取消提醒，没有聊天内任务/提醒查询。
- 用户问“你还记得我讲的笑话/我喜欢哪个？”：同 thread 历史与跨 thread 显式知识边界不清楚，没有“你记得我什么/忘掉”的可见操作。
- 用户问天气：当前无 web 工具；这是 MVP 范围外，不应当当作 bug。
- 19/19 deliveries confirmed，0 unknown/rejected，readiness 正常；没有出现需要回滚的故障。

## P0：先补齐对话中暴露的核心体验

### 1. 聊天内任务/提醒可见性（代码完成）

- 已新增只读 `list_reminders` / `list_tasks`：
  - 只列当前 tenant/bot/频道 scope；
  - 返回未完成/到期/unknown/rejected 的简短状态，不返回其他成员隐私；
  - 不改期、不取消、不发送。
- 验收：
  - 用户问“我有哪些待办/提醒”能用一次工具调用回答；
  - 空列表明确回答“没有”，不编造；
  - scope 隔离、状态映射和 no-mutation 有 PG/HTTP 回归；
  - 真实 Slack 一次 smoke 已通过（`list_tasks`；`list_reminders` 别名仅单测）；管理页/API 仍可查全量。
- 风险：任务查询可能暴露未知/blocked；默认只给 owner/当前频道摘要，详细项由管理页看。

### 2. Memory 策略与可见性（代码完成）

- 已实现：
  - 同 thread：模型上下文历史；
  - 跨 thread：仅显式 `remember` 的 channel-scope 知识；
  - 新增只读“你记得我什么”摘要/查询；
  - 已实现两步停用：`forget_memory` 只发 confirmation token，`confirm_forget_memory` 必须在后续用户消息消费；
  - 可选 opt-in 自动记忆，默认关闭；不得隐式无限记忆。
- 验收：
  - 新 thread 只能 recall 显式知识，不把同 thread 闲聊当长期事实；
  - forget 只停用目标知识，不删审计，不影响其他 scope；
  - 回答带来源；跨 thread `list_memories` 已通过一次 smoke；两步 forget 的请求路径已验证，confirm 成功路径待新 trial 重验。
- 待 owner 决策：是否要自动记忆、保留期限、谁可查询/删除。

### 3. Trial 运营闭环

- 管理页 unknown resolve 按钮（当前只有 API/curl）；
- 明确告警阈值/通知渠道（当前只有 5 分钟日志）；
- 新 trial 的启动/截止/停止 runbook 形成 checklist，避免手工遗漏；
- 正式团队前的成员 opt-in 和 Slack CLI 复核流程。

## P1：有证据后再投入

1. **窄 web_search**：搜索 API、top N 摘要、URL/时间、引用、出站 allowlist、速率限制、prompt-injection 处理；不做任意浏览器/通用 HTTP。
2. **多用户/组织治理**：成员身份、opt-in、RBAC/SSO、配额、审计；扩真实团队的前置。
3. **任务能力**：周期提醒、snooze、日历集成、改期/取消确认；不先做 Plan DAG。
4. **知识质量**：冲突/过期/来源可信度、管理页 curation、检索排序；向量检索只在关键词 recall 数据证明不够时引入。
5. **Chronotope 硬化**：跨仓库契约 CI、真实 Slack 故障矩阵、run cancellation/预算、审批/HITL（若工具需要）。
6. **生产化**：`/metrics` 告警、HA/PITR、systemd/Linux 目标宿主、成本预算。
7. **多 Bot/peer**：只有单 Bot 试用证明并行协作有明确收益后再产品化；当前 lab 仍 test-only。

## P2：生产能力线（不在 M1/M2 实现）

执行、工作区、浏览器和不可信工具在生产中是必要的，但必须作为独立 capability tier，不能给当前 native-tools agent 打开通用 executor。架构、隔离、审批、产物和分阶段计划见[生产能力线](生产能力线-执行与工作区.md)。

## 明确不在 M1/M2 做

- 任意浏览器/sandbox/代码执行；
- 向量数据库/通用 Record API；
- 多 Bot/peer 产品化；
- 第二组织/SSO/RBAC 大平台；
- 在未重新签核的情况下重启 trial 或扩员。
