# 生产能力线：执行、工作区、浏览器与不可信工具

状态：P2 生产规划；不属于当前 MVP，也不进入下一期 M1/M2 默认范围。

这些能力在生产中是必要的，但不能通过给现有 Bots `application_profile` 打开通用 executor 来实现。应新增独立的 **capability tier**，由 Bots 做授权/政策/审批/业务审计，Chronotope 做隔离执行，双方通过新契约协作。

## 能力分类

| 能力 | 执行面 | 默认信任 |
|---|---|---|
| 文件/工作区读取、列表 | 工作区服务/隔离文件 API | 默认只读、租户/run 绑定 |
| 文件写入、产物生成 | 工作区 + RustFS 对象存储 | 需策略/审批、保留期、hash |
| 代码生成/执行 | 隔离 sandbox executor | 默认无出站网络、资源/时间上限、审批 |
| 浏览器/网页操作 | 隔离 browser executor | 出站 allowlist、临时 profile、审批 |
| 不可信工具/MCP 调用 | tool gateway | 逐工具 allowlist、schema、auth、审批 |
| 窄 web search | Bots application tool | 低风险，不需要 sandbox；引用/出站限制 |

## 架构边界

- **Bots**：租户/频道/成员授权、capability policy、审批、知识/任务状态、产物引用、最终回答、审计和用户可见引用。
- **Chronotope**：run/harness/timer、sandbox/browser 生命周期、executor driver、资源配额、网络策略、产物上传/下载的受控执行。
- 不把 Bots 的任务/知识/审批状态搬进 Chronotope；不把 sandbox 主机/镜像管理搬进 Bots。
- 当前 native-tools agent 仍保持 `application_profile`，不需要也不应该默认获得 bash/browser/network。

## 每 run 的 capability manifest

未来 run 需要显式声明能力，例如：

```text
workspace.read
workspace.write
code.exec
browser.use
tool.invoke:<allowlisted-ref>
```

规则：

- 默认拒绝；按 tenant/scope/role/capability 授权；
- 能力不能由模型 arguments 自行提升；
- 写/执行/浏览器/外部副作用需要审批或明确 policy；
- 每个 run 有预算（CPU/内存/时间/网络/工具次数/产物大小）；
- 能力、审批、产物、网络拒绝和最终结果可审计；
- 不把长期凭据注入 sandbox；使用短期、最小权限凭据。

## 隔离与安全

- 每个 run 独立 sandbox/container，非 root、只读基础镜像、无宿主挂载；
- 固定镜像 digest、seccomp/AppArmor、资源/时间上限、kill switch；
- 默认无出站网络；按 capability 配置域名/端口 allowlist、DNS 和代理；
- 浏览器使用临时 profile，不共享 cookie/登录态；
- 文件/产物走 RustFS，manifest/hash/TTL/tenant scope，不把任意宿主路径暴露给模型；
- 外部网页/文件内容标记为不可信；不得因内容中的指令扩大工具权限；
- 产物扫描/大小限制；审计保留策略和删除路径；
- 失败分类、取消、超时和预算耗尽必须有明确错误码，不静默重跑有副作用操作。

## 分阶段建设

### P2.1 工作区只读 + 产物引用

- 列目录/读文件/产物元数据；tenant/run 绑定；只读；
- RustFS 引用、hash、TTL；
- 真实 Slack 工具 smoke 和权限负测。

### P2.2 工作区写入 + 审批 + 产物

- 写入/生成产物，审批、配额、保留/删除；
- 产物不直接回传模型，只返回引用/摘要；
- 审计和产物扫描。

### P2.3 代码执行 sandbox

- 无网络默认；镜像 digest、非 root、资源/时间限制；
- 审批/策略、stdout/stderr/产物上限；
- 失败/超时/取消语义；不能访问宿主或 Bots/Chronotope 内部网络。

### P2.4 浏览器/网页操作

- Playwright/browser executor，临时 profile，egress allowlist；
- 截图/HTML/文本产物，引用与保留；
- 审批、域名策略、下载限制、prompt-injection 处理。

### P2.5 不可信工具/MCP gateway

- 逐工具 allowlist、schema、auth、租户 scope；
- 审批、速率/预算、结果大小、失败分类；
- 不因工具描述/返回内容自动提权。

窄 `web_search` 可早于 P2.3/P2.4，作为 Bots application tool；不需要 sandbox，但仍需引用、出站 allowlist 和 prompt-injection 防护。

## 契约需要新增

- capability descriptor/manifest 与授权结果；
- sandbox/browser 生命周期、executor driver、资源/网络策略；
- artifact 引用、hash、TTL、下载/删除；
- approval/HITL 请求与结果；
- 取消、deadline、预算、超时、错误分类；
- per-run 网络拒绝/工具调用/产物审计；
- 跨仓库契约 CI 和版本兼容矩阵。

## 非目标

- 不默认给普通聊天开启 executor；
- 不提供任意宿主文件/网络/凭据访问；
- 不在 M1/M2 期间实现这些能力；
- 不把 sandbox 作为 web search 的替代；
- 不因为“Chronotope 有 executor”就跳过 capability policy。

## 与当前路线的关系

- M1/M2（list_tasks、memory）仍是 Bots 独立工作，不需要 sandbox；
- P2 先做 workspace/artifacts，再做 code/browser/untrusted tools；
- 正式团队 trial 可以先于 P2，但涉及外部写/执行前必须有 capability policy/审批；
- Chronotope 的 P0 工作（契约 CI、动态 target、错误分类）仍是 P2 的前置基础。
