## 4. 配对结果

环境：真实 Chronotope API/worker/harness、真实 `claude-sonnet-4-6`、两个隔离 test tenant、只连接计数 Slack sink；产品代码 `30b0dfa`，测试 harness 当时尚未提交（报告 `code_dirty=true`）。两臂所有 case 都完成，无 harness error，所有最终消息与提醒在 sink 均有 confirmed receipt。

| case | baseline | candidate |
|---|---|---|
| `trace_recall` | 失败：列出 `初版记录 2026-10-18` 和 `2026-10-20` 两条 | 通过：只列 2026-10-20、b4e8ee3、`sop_fixture_restart_review` |

| `missing_recall` | 通过 | 通过 |

配对判定：

- 目标改进成立：baseline 失败、candidate 通过。
- candidate-only guard regression：**无**。
- 共同失败：`reminder_relative` 的 caveat 短语检查；两臂语义相同，是 checker 措辞过窄，不是候选引入。
- baseline-only 失败：`single_recall` 的日期格式；baseline 语义正确，是 checker 格式过窄。
- `trace_recall` 的最终文本差异是真实行为差异，不是格式问题。

## 7. 边界

- 一个真实模型 alias、一个 workspace/测试频道、一个 Bot；上游模型版本仍标记 unknown。
- 一个 SOP 改进、一个目标 case 和四个 guard；fixture 是在 v1 null 结果后设计的，不构成独立大规模评测。
- 两处 checker 误报已保留并说明；没有事后改写原始结果。
- 没有自动提案、自动批准、评测服务、灰度平台或长期记忆效果评估；report 是本地 JSON。
- 发布后的真实知识/任务不删除；开发重建仍可能清空数据，不能替代保留数据的故障恢复验证。
- 测试 tenant 的 native 资产与 sink 数据留在开发 PG/本机；不写回组织 Bot。
